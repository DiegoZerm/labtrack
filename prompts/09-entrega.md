# 09 · Preparar la entrega

```text
Revisa LabTrack como si fueras otra persona que recibe una copia limpia.
Comprueba el README, los requisitos y los comandos de preparación,
migración, creación de usuarios, arranque, pruebas y parada.

Verifica que no se incluyan .env, contraseñas, tokens, datos locales,
entornos virtuales ni copias de seguridad. Conserva .env.example.
Comprueba que el ERD y el contrato coincidan con el código final.

Para la ruta avanzada, revisa Dockerfile, Compose y el workflow de CI.
Aclara si el workflow está en la raíz de un repositorio propio o sigue
siendo una plantilla anidada. No afirmes que GitHub Actions se ejecutó
si solo revisaste el archivo o corriste los comandos localmente.

Prepara una demostración de cinco minutos: entrar, crear un proyecto y
experimento, editar, probar permisos y recuperar los datos tras reiniciar.
Indica qué parte implementé yo y qué parte venía en la plantilla.

Entrega una lista corta de pendientes reales. No hagas commits, push,
crees un PR ni publiques un servidor.
```
